# Agent F — P2.7 class header generator + DishonoredGame class inventory

## What changed

- `resources/tools/ida/export_types.py`: enums are now dumped into `types.json` under `"enums"`
  (`name`, `size`, `is_bitmask`, `members[{name,value}]`, values sign-corrected by width). Ran on
  `resources/docs/idb/shipping2012_agentF.i64`; `types.json` / `sizes.csv` / `all_types.h` regenerated
  (39,964 UDTs, 20,051 enums, all 4 bytes wide).
- `resources/tools/symbols/gen_classes_header.py` rewritten:
  - class list from the `PrivateStaticClass` globals (2,536) plus `classes.csv`; `classes.csv` alone
    only holds the 1,036 classes whose inline `StaticClass()` got an out-of-line copy. Module = majority
    module of the class's member functions in `functions.csv` (StaticClass rva as fallback). Abstract =
    no `InternalConstructor` function (DECLARE_ABSTRACT_CLASS).
  - base classes from the `is_base` members (multiple inheritance kept: interfaces, `FExec`,
    `FArchive`, `FCurveEdInterface`); `UObject` gets `DECLARE_BASE_CLASS`.
  - members in reference style: `//## BEGIN/END PROPS`, `BITFIELD x:1;` runs with `SCRIPT_ALIGN;`
    after bitfield/BYTE runs, `class UFoo*` spelling, `TArrayNoInit<...>` with default allocators
    stripped, function-pointer members as proper declarators; exact offset/size in a trailing comment.
  - enum block (`enum E {..., E_MAX}` + `FOREACH_ENUM_*`) for every enum referenced by an emitted
    member or declared in the module's .uc / reference header; script enums absent from the PDB listed
    in a comment.
  - script structs (from .uc `struct native` or reference `struct F...`) emitted before the classes in
    dependency order.
  - natives: `DECLARE_FUNCTION(execX);  // rva, GNatives idx` per class, then
    `AUTOGENERATE_FUNCTION(cls,idx,execX);`, `AUTO_INITIALIZE_REGISTRANTS_<MOD>`, `MAP_NATIVE` tables
    and `VERIFY_CLASS_SIZES`, plus a `<Module>Names.h`-style `AUTOGENERATE_NAME` block of native
    function names grouped per class (the reference only uses AUTOGENERATE_NAME for event names; the
    natives themselves are the AUTOGENERATE_FUNCTION list, both are emitted).
  - COMDAT folding: `natives.csv` has one name per address. When `pdb_functions.csv` exists (uncommitted,
    regenerated by `dia_dump.py`) the folded `(class, exec)` pairs are restored from the DIA names per RVA
    and from the `IMPLEMENT_FUNCTION` dynamic initializers (`'<Class>exec<Func>Temp'`, 2,607 registrations
    vs 2,166 addresses). 73 registered pairs have no exec symbol at all (comment says so, rva 0x0).
  - split: script-declared classes (stem has a DFSDK .uc or a reference `*Classes.h` declaration) first,
    then a "classes without a known script declaration" section.
  - `--diff-reference` (semantic diff against the reference `<Module>*Classes.h`) and
    `--inventory <md>` (DFSDK .uc cross-reference). The .uc parser handles `class`/`interface`, `var`
    (multi-name, dims, templates), `enum`, `struct ... extends`, `native ... function/event`, and
    un-comments the DFSDK's `udk`-tagged comments (retail declarations hidden for UDK 2010).
- Generated: `resources/reference/CoreClasses.pdb.h` (44 classes), `resources/reference/DishonoredGameClasses.pdb.h`
  (1,485 classes, 180 structs, 173 enums, 36k lines, 16 s), `resources/docs/dishonoredgame_class_inventory.md`.

## Core: generated vs reference CoreClasses.h

- Same 7 script-declared classes (`UCommandlet`, `UHelpCommandlet`, `UComponent`, `UDistributionFloat`,
  `UDistributionVector`, `UInterface`, `USubsystem`), same bases, same members in the same order
  (0 only-pdb, 0 only-ref, 0 order mismatches), same enums (`EDistributionVectorLockFlags`,
  `EDistributionVectorMirrorFlags` with identical values).
- Structs: `FRawDistributionFloat`/`FRawDistributionVector` match; `FMatineeRawDistributionFloat` is not in
  the 2012 PDB (10897 addition).
- Natives: `UDistributionFloat::execGetFloatValue` / `UDistributionVector::execGetVectorValue` match.
  Dishonored registers `UCommandlet::execMain` (and the folded copy on `UHelpCommandlet`) as a native;
  the reference has `Main` as an event only.
- `UObject`: 419 natives in the PDB vs 260 `MAP_NATIVE` entries in the reference. The 174 extra are the
  bytecode opcode handlers (`execLocalVariable`, `execJump`, `execHighNative0..15`, casts...) that the
  reference binds through the static `GNatives` table instead of `MAP_NATIVE`; 15 reference natives are
  missing from 2012: `ProfNode*` (5), `*Guid*` (5), `GetLanguage`, `GetRotatorAxis`, `GetScriptTrace`,
  `ImportJSON`, `Normal2D`.
- The 37 remaining Core classes with a `PrivateStaticClass` (UObject, UField, UProperty family, UStruct,
  UState, UClass, UFunction, ULinker*, UPackage, UMetaData, USystem, UTextBuffer, UExporter, UFactory,
  UTextBufferFactory...) are native-only (declared in UnObjBas.h/UnClass.h in the reference) and go to the
  second section. Reference `AUTO_INITIALIZE_REGISTRANTS_CORE` lists exactly these 44 classes.
- IDA quirk carried over: `UObject::Outer` is typed `UEngine*` in the PDB import.

## DishonoredGame inventory (see resources/docs/dishonoredgame_class_inventory.md)

- 1,485 UObject classes attributed to DishonoredGame; 220 have a DFSDK .uc (206 classes + 14 of the 22
  interfaces), 1,265 have none (the DFSDK is a map-making subset: all `UStateNPCMaster*`,
  `UDisItemContext_*`, `UDisTweaks_*` beyond the 30 shipped, `ADisProjectile*`, weapons, powers, UI...).
- 7 .uc without a 2012 class: `DisDLC06SeqAct_EndDLC06`, `DisDLC06SeqAct_NPCAddPutPocketInteraction`,
  `DisDLC07PullTargetInterface`, `DisDLC07PullerInterface`, `DisNPCAttachmentOwnerInterface` (2013 DLC
  additions), `DisRatPointLight`, `DisRatSpotLight`. `UDisEngineTweaksInterface` lives in Engine.
- Of the 220 cross-referenced classes: 164 match exactly (names, order, natives, enums); 0 classes have
  common members out of .uc order; 30 have PDB-only members, 28 have .uc-only vars (2013 additions such
  as `m_bExpectingPutpocket`, `OnNPCAddPutPocketInteraction`, DLC06/07 enum values), 6 have native
  differences, 12 have enum value differences (all 2013 growth, e.g. `eDisPawnHitReactionType` 9 -> 11,
  `EDisTutorialNote` 34 -> 44, `EDisUIMap` 15 -> 25). 3 base-class differences are DFSDK hand edits
  (`DisRatSpawner extends Actor`, `DisSeqAct_OpenCraftsmanStore extends Object`,
  `DisTweaks_AIBrainProcess_RatCrusher extends Object`).
- 6 script enums have no PDB type (`EAINoiseContext_HelpType`, `EDLC06EndGameItems`, `EDisObjectivePriority`,
  `ESaveLoadMode`, ...); the .uc struct `DisArmor` has no PDB type.

## Caveats for Phase 3

- Class flags (`CLASS_Transient`, `CLASS_Config`...) and `DECLARE_CASTED_CLASS` cast flags are not in the
  PDB; every class is emitted with flags 0. Read them from `UClass::ClassFlags` at runtime or the .uc.
- Enum-typed script properties appear as `BYTE` (their real C++ storage); native members keep the enum.
- Delegate properties show as `FScriptDelegate __X__Delegate` (UE3's real name), not as the `delegate` decl.
- `pdb_functions.csv` is required for the folded-native recovery; without it the header degrades to the
  `natives.csv` set silently.
