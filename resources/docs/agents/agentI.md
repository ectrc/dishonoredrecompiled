## Serialization layouts relied on (Ver 801 / LicenseeVer 30, PC cook, loading)

Verified by exact `SerialSize` consumption on ~60k field exports per tree; source lines are UE3 10897 unless marked Arkane.

Package level:
- `FPackageFileSummary` as in `read_package_summary.py`; the `FCompressedChunk` table (`UncompressedOffset, UncompressedSize, CompressedOffset, CompressedSize`) sits after `CompressionFlags`. Summary offsets (`NameOffset` etc.) are in *uncompressed-file* coordinates; each chunk is placed at its `UncompressedOffset` (`Package.read` maps a range to the chunk that contains it, lazily decompressing).
- Chunk body (`FArchive::SerializeCompressed`, UnArchive.cpp:146): `FCompressedChunkInfo{PACKAGE_FILE_TAG, block size 0x20000}`, `{CompressedSize, UncompressedSize}` of the chunk, one `{c, u}` pair per 128 KB block, then the LZO1X blocks back to back. `Core.upk` 2013: one chunk 141+193512 in two blocks (29113/131072, 16232/62440).
- Name entry (UnName.cpp:983): `INT len` (negative = UTF-16), chars incl. NUL, `QWORD Flags`. Cooked name tables are sorted (`!`, `!=`, `$`, ...). `FName` on disk = `INT index, INT number` (`Name_{number-1}` when number != 0).
- `FObjectImport` (UnLinker.cpp:316): `ClassPackage, ClassName (FName), OuterIndex, ObjectName` = 28 bytes.
- `FObjectExport` (UnLinker.cpp:267): `ClassIndex, SuperIndex, OuterIndex, ObjectName, ArchetypeIndex, QWORD ObjectFlags, SerialSize, SerialOffset, ExportFlags, TArray<INT> GenerationNetObjectCount, FGuid PackageGuid, PackageFlags`. `ClassIndex == 0` means the export is a `UClass`.
- Object index: `> 0` export `idx-1`, `< 0` import `-idx-1`, `0` null. Paths are `Outer.Name`; a `Package`-class export with no outer (forced-export package root inside a seek-free package) is the path root, otherwise the file name is.

Per export (every field export starts like this):
- `UObject::Serialize` (UnObj.cpp:1596): no `RF_HasStack` on any field export (asserted); `INT NetIndex` (`SerializeNetIndex`, value is 0/-1, `UObject` has no such member); then tagged script properties ending in the `None` tag **unless the export is a `UClass`** (`SerializeScriptProperties` is skipped for `UClass`). `FPropertyTag` = `Name, Type (FName), INT Size, INT ArrayIndex, [StructProperty: FName StructName | BoolProperty: BYTE (>=673) | ByteProperty: FName EnumName (>=633)]`, then `Size` bytes. Field classes have no script properties, so this is 8 bytes of `None` for every non-class field.
- `UField::Serialize` (UnClass.cpp:80): `UField* Next`.
- `UStruct::Serialize` (UnClass.cpp:1026): `UStruct* SuperStruct` (>=756), `UTextBuffer* ScriptText`, `UField* Children`, `UTextBuffer* CppText`, `INT Line`, `INT TextPos`, `INT ScriptBytecodeSize`, `INT ScriptStorageSize` (>=639), `BYTE Script[ScriptStorageSize]` (skipped, not disassembled). The `ScriptText/CppText/Line/TextPos` block **is present** in the PC cook (`IsPackageCookedForConsole` is false); the `!CONSOLE` branches are all taken.
- `UScriptStruct::Serialize` (UnClass.cpp:1443): `DWORD StructFlags`, then the struct defaults as tagged properties (`WantBinaryPropertySerialization` is false for a linker). Default tag names are kept in `defaults`; values are skipped.
- `UState::Serialize` (UnClass.cpp:1556): `DWORD ProbeMask`, `WORD LabelTableOffset`, `DWORD StateFlags`, `TMap<FName, UFunction*> FuncMap` (count + pairs).
- `UClass::Serialize` (UnClass.cpp:2221 + Arkane deltas from `serialization_delta_core.md` 3.4): `DWORD ClassFlags`, `UClass* ClassWithin`, `FName ClassConfigName`, `TMap<FName, UComponent*> ComponentNameToDefaultObjectMap`, `TArray<FImplementedInterface{UClass* Class, UProperty* PointerProperty}> Interfaces`, `TArray<FName> DontSortCategories` (>=603), `HideCategories`, `AutoExpandCategories`, `AutoCollapseCategories`, `UBOOL bForceScriptOrder` (>=749), **`FName m_DropdownCategory` (LicenseeVer >= 10, Arkane)**, `FString ClassHeaderFilename`, `FName` dummy `DLLBindName` (>=655, always `None`), **`DWORD m_OtherClassFlags` (Ver >= 796, Arkane; 0 on every class in both trees)**, `UObject* ClassDefaultObject`. **No `ClassGroupNames`** (reference 789) — inserting it breaks every class. The editor block (categories, dropdown, header filename) is present in the PC cook; `header_filename` is set on 2,358 of 3,043 classes (2013), `force_script_order` on 490, `dropdown_category` on 58 (`NPC`, `MeleeCombat`, `Power`, `Equipment`, `Soiree`, `RangedCombat`, `AnimState`, ...).
- `UFunction::Serialize` (UnClass.cpp:2636): `WORD iNative`, `BYTE OperPrecedence`, `DWORD FunctionFlags`, `WORD RepOffset` if `FUNC_Net` (0x40), `FName FriendlyName` (present, PC cook).
- `UConst::Serialize` (UnClass.cpp:2764): `FString Value`. `UEnum::Serialize` (UnCoreNative.cpp:438): `TArray<FName> Names`.
- `UProperty::Serialize` (UnProp.cpp:145): `INT ArrayDim`, `QWORD PropertyFlags`, `FName Category`, `UEnum* ArraySizeEnum` (present, PC cook), `WORD RepOffset` if `CPF_Net` (0x20). Subclasses: Byte `UEnum* Enum`; Object/Component `UClass* PropertyClass`; Class `PropertyClass, MetaClass`; Interface `UClass* InterfaceClass`; Struct `UScriptStruct* Struct`; Array `UProperty* Inner`; Map `Key, Value`; Delegate `UFunction* Function, UFunction* SourceDelegate`; Bool/Int/Float/Name/Str nothing (`UBoolProperty::BitMask` only when neither loading nor saving).

Children order (`UField::Next` chain, what `UStruct::Link` walks): **properties are in declaration order; functions, structs, enums and consts are prepended** (reverse declaration order). `Object`'s list is therefore `[functions reversed] [structs/enums declared after the vars, reversed] [properties in order] [structs declared before the vars, reversed: QWord, Pointer]`. Function children are params in order (`ReturnValue` last among params) followed by locals. The JSON keeps the on-disk order.

## Facts found (2013 retail unless noted)

- **Null exports**: the 2013 cooker zeroes stripped exports instead of removing them (all-zero `FObjectExport`, name `None`, `SerialSize 0`, `ClassIndex 0`). `Engine.upk` 152, `OnlineSubsystemSteamworks.upk` 145, `DishonoredGame.upk` 101, `GameFramework.upk` 12. The 2012 tree has none. `Package.is_null_export` skips them; they must not be treated as `UClass` exports.
- **Classes stripped from Engine in 2013**: 71 classes present in 2012 `Engine.upk` are gone in 2013 (Apex/PhysX destructibles, Fluid*, Foliage*, Fractured*, GameplayEvents*, PBRuleNode*, ProcBuilding, CameraAnim/CameraShake, LightProbe*, ...) and 6 from `GameFramework` (GameCrowdAgentBehavior, GameExplosion*, GameStateObject, GameStatsAggregator). 21 removed from `DishonoredGame` (`DisAlcoholPickup`, `DisLightSampler*`, `DishonoredStealthProbe*`, `DisSeqAct_*HeartTarget`, ...). 2 added to Engine (`DisOnlineLeaderboards`, `DisOnlineLeaderboardsInterface`), 355 to `DishonoredGame` (DLC05/06/07 gameplay, `DisDLC05ChallengeRule_*`, `DisDLC06*`, `DisDLC07*`, ...).
- **Content script packages live inside other files.** `DishonoredGameContent` (60 classes 2013 / 56 in 2012) is not shipped as its own `.upk`: 37 of its classes are forced exports inside `DishonoredGame.upk`, the other 23 (`DisDamageType_Arrow*`, `DisNPCAnimDefinitions*`, `DisContactType_*`) only exist as forced exports in level packages (`Startup.upk`, `L_*_Script.upk`, `FT_Combat.upk`/`FT_Routine.upk` in 2012). `DishonoredGameDLC06Content` (24 classes) and `DishonoredGameDLC07Content` (16) exist only inside the DLC06/DLC07 level packages (`DLC06_DaudBase_Script.upk`, `DLC07_Twk_Player_Daud_SF.upk`, `L_DLC07_*_Script.upk`, ...). There is no separate DLC script `.upk`; the DLC's engine/gameplay classes are in the 2013 `DishonoredGame.upk`. `OnlineSubsystemPC.upk` (1 class) is a script package I had not been told about; included.
- **Forced-export copies are identical**: 1,276 class exports across 99 DLC packages and the copies in the base-game level packages all match the first occurrence (super, flags, full member signature) — `copy_mismatches` is empty in both trees. Max 169 copies of one class (2013), listed in `also_in`.
- **Native indices did not change**: 189 numbered natives (iNative != 0) in both trees, 0 changes. All numbered natives are in Core/Engine; Arkane natives are unnumbered (`iNative 0`, bound by name).
- **Delta totals** (2012 -> 2013): classes added 401, removed 98, changed 258; members added 453, removed 160, reorders 7 (`DisGFxMoviePlayerMainMenu`, `DisGFxMoviePlayerMenuBase`, `DisGFxMoviePlayerNote`, `DisMovableLimb`, `DisTweaks_MeleeAttack`, struct `DisTweaks_PlayerStats.PlayerStatInfo`, `StatePlayerMasterInDialog`; first differing member named in the delta), enum value changes 35 (e.g. `EAIStimID` +10 values with 105 renumbered, `EProfileSettingID` +22/-1 with 80 renumbered, `ESaveGameSlot` +3 with 14 renumbered, `EDisPowerWheelItem` replaces the `DPWI_DLCItem0x/DLCPower0x` placeholders), super changes 8 (four `DisBehavior*` classes now extend the new `DisBehaviorAttentionBase`, three `AIStimStruct_*` structs now extend `AIStimStruct_AttentionBehaviorBegin`), class-flag changes 10. `Const` count 179 -> 140.

## Not decoded / limitations

- Script bytecode is skipped (`ScriptStorageSize` bytes); `script_size`/`script_storage_size` are recorded per class/function/state.
- Struct defaults and class default objects: only the tag names of `UScriptStruct` defaults are kept; CDO contents are not parsed.
- Property offsets / class sizes are not computed (that is `UStruct::Link`, agent H's `native_class_sizes` and the C1 reconciliation); the JSON has everything needed to replay `Link` (kind, array dim, struct/enum refs, flags, order).
- `FuncMap`, `ComponentNameToDefaultObjectMap`, `Interfaces`: names only (object references dropped).
- The `also_in` lists cover copies in files I scanned; `_LOC_*` packages were excluded.
- `ULinkerLoad::FixupImportMap`/`RemapClasses` fixups are not applied (irrelevant for 801 packages).
- `read_package_summary.py` was not modified; the chunk table is re-read by `read_chunk_table`.
