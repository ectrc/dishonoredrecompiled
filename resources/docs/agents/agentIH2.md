# Agent IH2 (wave 26, PHASE23 IH2): a line is audible

Second package of the IH program. AK::SoundEngine playback now runs on ported Audiokinetic 2012.1 code. That covers the
message queue and audio thread, the playing manager, the renderer and PBIs, the lower engine and its VPL pipeline, the
packed-codebook Vorbis decoder, the PCM and ADPCM sources, and a DirectSound sink. Conversation lines in the opening are
decoded, mixed and sent to the Windows output device, and each one ends when its media ends.

The base commit is `8254e4e` (main at hand-back). The worktree is `build/agentIH2_wt`. `build/agentIH2_sync.py` lists 126
files. Nothing was committed.

## 2. Named deviations (each in its file banner)

**IH3 seams**
- RTPC, switch, state and trigger calls are not queued. They keep the existing books, and SetState also writes CAkStateMgr.
- GetAudioParameters folds properties and ranges with no RTPC, state or ducking.
- The 3D branch of `CAkVPLSrcCbxNode::GetVolumes` mixes a 3D voice the way the 2D branch does: base pan, effective volume, no attenuation, cone or obstruction.
- Paths are not created, and the path manager does not exist.
- Query::GetMaxRadius returns -1, and the GetEnvironment* queries return 0.
- PlayAndContinue: only the PDB layout and the audio-manager calls are ported, because it needs continuous containers.

**IH4 seams**
- Bus and source insert effects: `CAkBusFX::SetInsertFx` and AddPipeline's GetFX leave every slot empty.
- Environmental (aux) sends: `GetEnvironmentalBus` is not ported, so an aux-sending voice mixes its dry path and its obstruction LPF only.
- Source plug-ins: AkSilenceSource sounds take retail's own failed-play path.
- SetEffect, SetEnvironmentVolume(s) and BypassEnvironment answer AK_Success.

**Other deviations**
- **Sink window and focus.** Retail passes GGameWindow and clears `bGlobalFocus`, so DirectSound mutes the game whenever its window loses focus. Here the sink uses the desktop window and keeps `bGlobalFocus` TRUE, as the brief requires: audible windowed and unfocused.
- **No feedback (motion) pipeline**, and no default-device-change reset (CAkMMNotificationClient / InternalWindowProc).
- **API calls after Term return AK_Fail.** Retail dereferences a NULL CAkAudioMgr there. This is not built into the staged exe; see §4.
- **Diagnostics.** `-akwav` writes the sink input (under g_csMain). `-akdiag` adds lines for every prepared media, every PrepareEvent result, every playing id's end with its buffer tick, and every duration.
- **IH1's AkMediaEntry::GetMedia was wrong and is fixed to retail (0x92a5f0).** IH1 took no reference on the entry and did not skip a slot being unloaded.

## 3. Measurements

### CoreSmoke

CoreSmoke passes **145 of 145** (`build/agentIH2/coresmoke_run8.log`). It was run from the repo root with `WWISE_SMOKE_CSV=build/agentIH1/hirc_counts.csv`; the threshold was ≥127.

**Vorbis decode of voice media 0x5c7ca16c** (mono, 44.1 kHz):
- **Length and checksum:** 117,526 frames, which equals ffmpeg's frame count. Sample sum 36,897, peak 23,476.
- **Sample-for-sample comparison:** the media was rewrapped to Ogg and decoded by ffmpeg (`resources/tools/wwise_vorbis_ref.py`). SNR is **73.1 dB**, max |diff| 1 LSB.
- **Through CAkSrcBankVorbis:** all 117,526 frames come out, and it ends with AK_NoMoreData.
- **Codebook reference:** released.
- **RMS-per-1024 check:** its floor was raised to 64 for near-silent blocks. Block 0 has a reference RMS of 2.16, which the table rounded to 2, so 1 LSB of rounding read as 2.3%.

**Pipeline check** (`TestPipeline` in `WwiseSmoke.cpp`): PostEvent(0x57447bbe) goes through the action, PBI, Vorbis source, pitch node, mix bus, final mix and sink, and `-akwav`'s writer captures the result.
- **AK_Duration:** 2665.0 ms (media 2664.99 ms).
- **AK_EndOfEvent:** fired once, at the media end.
- **Captured output:** stereo, 48 kHz, peak 10,435, RMS 1,411. The audible span is **2.6622 s** against **2.6650 s** of media.

## 4. Where the brief was wrong (with the measurement)

1. **"Media preparation IH1 deferred" is not optional.** IH1's note says "Dishonored never calls PrepareEvent". In fact every conversation line is PrepareEvent'd immediately before its PostEvent (IH2a.log, line 2492: `PrepareEvent 0x57447bbe: structure only`). The banks are only *prepared* StructureOnly, so without PrepareNodeData/LoadSingleMedia no voice has media. In build 1 every line ended 1 frame after its post, with no AK_Duration.
2. **"The opening's PostEvents".** Before the conversations the opening posts one event, `Snd_Fade_In_All` (0xa087ef13). It is a fade action (type 0x1204) with no media; it ends after its 1.8 s transition.
3. **The packed codebooks are not called `packed_codebooks`** in the 2012 PDB. They are `g_packedCodebookData` (u8[71991], 0xd90d68) plus the `g_packedCodebooks` pointer table (u8*[599], 0xe3df78).
4. **Pieces listed as IH3 that IH2 needs.** CAkLEngineCmds, CAkTransitionManager, the actions' Execute, node play/activity counts, CAkBusCtx and the 2D half of CAkListener are all on the path of a single Play. 125 IH3 rows moved into IH2.
5. **PlayAndContinue is not IH2's.** It is runtime-only and is created by continuous random/sequence containers; no bank contains one. Only its layout and the audio manager's calls are here.
6. **"Sink as retail selects".** Retail's selection (GGameWindow, `bGlobalFocus` cleared) mutes an unfocused window. The brief also requires audio without focus, so the two cannot both hold; the sink keeps global focus (§2).
7. **Global callbacks run on the audio thread.** The game's DisAkGlobalCallbackFunc is a behavioral extension that retail calls from CAkAudioMgr::Perform on "AK::EventManager", not from RenderAudio on the game thread as the silent backend did.
8. **The base commit** moved 5 times during the package: ea91599 → 8254e4e.
